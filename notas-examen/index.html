Chuleta de C para el Examen

Notas conceptuales para pasar a mano · Yilmar · AvanzaTec · Temas: Etapas 1 a 9 + taller

0. Cómo partir cualquier ejercicio (el método)

  1. Lee el enunciado 2 veces. La segunda, subraya: qué funciones pide, qué salida exacta quiere, qué casos especiales menciona ("si la lista está llena…").
  2. Identifica la fuente de verdad: el contador que dice cuántos elementos son reales (ej. listSize, n). El arreglo guarda datos; el contador manda.
  3. Escribe primero la FIRMA de cada función (¿puntero o valor? — sección 4). El cuerpo después.
  4. Orden de ejecución: pedir → calcular → imprimir. Así se arman casi todos los programas.
  5. Compila con gcc -Wall -Wextra -g y prueba los casos borde (lleno, vacío, índice inválido), no solo el camino feliz.
  6. Nunca digas "listo" sin verificar: editar → guardar → mirar la línea con los ojos → compilar.

4. Regla de oro del paso de parámetros

Solo LEE un dato simple (int, float, char) → por valor: void f(int x)
MODIFICA un dato simple → por puntero: void f(int *x) y llama f(&x)
Arreglo o string → SIEMPRE llega como puntero: int arr[] ≡ int *arr. Se modifica directo, sin &.
Struct grande o que se modifica → por puntero: void f(Producto *p) → p->campo
Recuerda: si el main debe VER el cambio, la función toca la caja original → puntero. "El puntero es el puente entre el salón y la nota".
SímboloSignificadoEjemplo
&xla dirección (la "nota" de x)f(&x) · scanf("%d", &x);
*pel valor al que apunta p (leer o escribir)int v = *p; · *p = 5;
arr[i]equivale a *(arr + i)arr[3]
&arr[i]dirección del elemento iscanf("%d", &arr[i]);
LA REGLA QUE LO DOMINA TODO (Examen Prueba 2): cómo accedo a un elemento según la firma de la función.
Firma del parámetroCuándo la vesAcceso al producto i
Producto *inv (1 estrella)solo LEES o modificas elementosinv[i].campo — directo, SIN paréntesis
Producto **inv (2 estrellas)la función debe CAMBIAR a dónde apunta el puntero (realloc mueve el bloque)(*inv)[i].campo — con paréntesis SIEMPRE
Por qué el paréntesis: en C [] tiene MÁS precedencia que *. Sin paréntesis, *inv[i] se lee *(inv[i]) (primero indexa, luego desreferencia) = ERROR. Con (*inv)[i] primero sacas el puntero real (*inv) y luego indexas. "Desreferencia el doble puntero antes de indexar."

5. Punteros y aritmética de punteros

  • Punteros modifican el original, no copias: intercambiar(&a, &b) funciona; intercambiar(a, b) no (fotocopias).
  • Aritmética: ptr + 1 avanza UN elemento (no un byte). Por eso (est + i)->campo recorre el arreglo de structs, igual que est[i].campo.
  • El puntero nuevo de realloc puede ser distinto: siempre guarda el valor devuelto.
*ptr++ vs (*ptr)++: el primero avanza el puntero; el segundo suma 1 al valor apuntado. (El famoso *listSize++ era (*listSize)++).

6. Memoria dinámica (malloc / realloc / free)

  • malloc(cant * sizeof(Tipo)) — pide memoria cruda; calloc(n, tam) igual pero en cero.
  • sizeof SIEMPRE con el tipo: malloc(3 * sizeof(Producto)). Nunca sobre un puntero.
  • Revisar que no devuelva NULL (falló la memoria) y manejar.
  • realloc(ptr, nuevo_tam) — crece/encoge y puede MOVER el bloque.
  • Todo malloc → su free al final. Arreglo de punteros: free cada elemento + free externo.
if (n == capacidad) {                     // arreglo lleno
    Producto *aux = realloc(inv, 2 * capacidad * sizeof(Producto));
    if (aux == NULL) { manejar error; return; }
    inv = aux;                             // el puntero PUEDE haber cambiado
    capacidad *= 2;
}
¿Puntero doble (Producto **inv)? Solo si la función debe CAMBIAR a dónde apunta el puntero del main (un realloc movió el bloque). Si solo modificas elementos, el puntero simple alcanza.
La estructura CORRECTA de agregar (realloc): el if(está lleno) es SOLO para crecer la memoria; AGREGAR el dato y n++ van SIEMPRE, fuera de ese if. 
if (*cantidad < *capacidad) {              // NO: "si hay espacio"...
    // ...agregar aquí               // ESTO está MAL: solo agregaría
}                                     // cuando cabe, y si el dato llena
                                      // la capacidad, se pierde
// CORRECTO:
if (*cantidad == *capacidad) {        // 1) ¿está lleno? → SOLO crecer
    nuevo = realloc(*inv, 2*(*capacidad) * sizeof(Producto));
    if (nuevo == NULL) { error; return; }   // falló → salir y NO tocar nada
    *inv = nuevo;                           // ✔ después del return-check
    *capacidad *= 2;
}
int i = *cantidad;                    // 2) agregar SIEMPRE (fuera del if)
(*inv)[i].id = id;
strcpy((*inv)[i].nombre, nombre);
(*inv)[i].cantidad = cantidad;
(*inv)[i].precio = precio;
(*cantidad)++;
Código muerto tras return;: todo lo que escribas DESPUÉS de un return dentro del mismo bloque NUNCA se ejecuta (el return es el botón de salida). Ej. el error clásico: 
if (temp == NULL) { error; return; *inv = temp; }   // *inv = temp NUNCA corre
Las actualizaciones importantes van DESPUÉS del bloque if, no después del return.
Recuerda la analogía: un puntero NO es un arreglo hasta que le asignas memoria (malloc). Producto *p = NULL; = solo un puntero vacío. Recién con p = malloc(n*sizeof(Producto)) se comporta como arreglo (p[0], p[1]...). Y Producto *temp en el realloc guarda lo que devuelve realloc: un puntero al PRIMER Producto del bloque (los demás son contiguos).

8. Arreglos y ordenamiento

  • Un arreglo de N tiene posiciones 0 a N-1 (NO N). Salirte = comportamiento indefinido.
  • Recorrido con for: for(i=0; i<n; i++).
  • Máximo/mínimo: arranca con max = arr[0] después de llenar el arreglo, y recorre desde el índice 1.
  • Conteo/acumulador: n++ al agregar (el contador es la fuente de verdad).
  • Intercambio de dos posiciones: variable temporal (swap).
// Bubble sort (Etapa 4): burbujas que trepan los grandes al final
for (i = 0; i < n-1; i++)            // pasadas
    for (j = 0; j < n-1-i; j++)       // comparaciones (menos cada pasada)
        if (arr[j] > arr[j+1])        // si el de la izquierda es mayor → intercambiar
            { int tem = arr[j]; arr[j] = arr[j+1]; arr[j+1] = tem; }

13. Los fantasmas que ya cazamos (no volver a caer)

1. El punto y coma fantasma. if (x > y); — ese ; cierra el if y lo de abajo se ejecuta SIEMPRE. Mismo riesgo con for (...);.
2. *ptr++ vs (*ptr)++. El primero avanza el puntero; el segundo suma al valor apuntado (*listSize++ era (*listSize)++).
3. return 0; dentro de función void. Las void solo hacen return; (sin valor).
4. sizeof de un puntero. sizeof(sen) cuando sen es parámetro da 8. Para el largo → strlen.
5. Asignar arreglos con =. palabra = larga; no compila → strcpy o mover punteros.
6. strcat con un int. Espera cadenas, no caracteres sueltos ni índices.
7. Off-by-one. Índices de 0 a n-1. En borrados: i < n-1 (con <= pisas la última). En guardia de índice inválido: index >= n (no >).
8. Python en C (−1). No existe. El último elemento es arr[n-1].
9. Olvidar el & en scanf. Se lee basura o truena. (En %s y arreglos NO va).
10. División entera por descuido. suma/n con ambos int trunca → mi promedio .5 desaparece si no hay cast a float.
11. Cerrar el flujo olvidado. Archivos: fclose siempre; memoria: free de todo lo malloc. Pérdida = fugas.
12. Mezcla * vs **. Usar (*inv)[i] en una función que recibe Producto *inv (1 estrella) NO compila. Regla: 1 estrella → inv[i]; 2 estrellas → (*inv)[i]. (Examen Prueba 2).
13. Agregar dentro del if(está lleno). Si pones el "asignar dato + n++" dentro del if(cantidad == capacidad), solo agregas cuando está lleno (y el primero nunca se agrega). El crecer es aparte del agregar. (Examen Prueba 2)
14. Código muerto tras return;. Líneas importantes después de un return; en el mismo bloque no corren jamás (ej. *inv = temp; después de return; ).
15. "No encontrado" que devuelve 0. 0 es índice válido → el main cree que sí encontró y accede a basura. Devuelve -1 cuando no existe.

14. Cuando truena: diagnóstico express

El protocolo (lo más importante)

  1. Lee el PRIMER error del compilador. Ignora los de abajo: la mayoría son secuelas de ese primero.
  2. Arregla SOLO ese error → recompila → mira el primer error nuevo → repite.
  3. Nunca intentes arreglar 5 errores a la vez: uno arrastra a los demás.
  4. Si el programa corre pero da basura: el printf te cuenta la verdad — imprime las variables sospechosas ("verifica, no supongas").

15. Formatos, buffers y gotitas (lo que SIEMPRE se olvida)

Gotitas fáciles de perder

  • fgets guarda el '\n' al final del texto → matarlo con s[strcspn(s, "\n")] = 0;
  • Tras un scanf("%d", &x) queda un '\n' en el buffer que puede arruinar el siguiente fgets o %c → consumirlo con un getchar();
  • scanf("%c", ...) lee el salto de línea sobrante → el menú "salta" una opción. Limpia el buffer antes.
  • toupper / tolower úsalos solo garantizando que es letra (isalpha/isalnum).
  • En printf, los double van con %f; el %lf es solo de scanf.
  • return 0; solo en el main; las funciones void usan return; sin valor.

16. Recordatorios finales para transcribir a mano

  • Pregunta ante cada firma: ¿modifica? → puntero. ¿solo lee simple? → valor. ¿arreglo/string? → puntero. ¿struct que modifica? → puntero.
  • ¿1 ó 2 estrellas? 2 estrellas (**) en la firma = hay que (*inv)[i] y además el main debe ver el cambio de puntero (realloc). De lo contrario, 1 estrella normal.
  • El "si está lleno" es del crecimiento, no del agregado. Agregar siempre va fuera del if(capacidad).
  • Nada importante después de un return;.
  • Buscar-sí-actúo usar bandera; buscar-devolver usar -1.
  • Casos especiales AL PRINCIPIO (guardia + return;). El enunciado los menciona: "llena…", "vacía…", "índice inválido".
  • Empate → primera: actualizar solo con >, nunca >=.
  • Memoria: todo malloc → free; cada realloc → guardar el puntero nuevo y chequear NULL.
  • String: no =, no == → strcpy / strcmp; termina en '\0'.
  • Archivos: revisa NULL al abrir, cierra al terminar, fgets para leer líneas.
  • Fuente de verdad: el contador; los deslizamientos mueven datos. Dominas eso → dominas listas estáticas y dinámicas.
  • Verifica, no supongas: compila -Wall -Wextra, prueba camino normal Y casos borde.
  • Si el código tiene varias fallas: tíralo y reescríbelo limpio paso a paso, no lo parchees error por error.
